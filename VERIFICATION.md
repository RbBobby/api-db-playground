- Образы API и user-simulator успешно собраны из Dockerfile.
- Конфигурация Docker Compose прошла `docker compose config --quiet`.
- PostgreSQL и API запущены; оба healthcheck проходят.
- Миграция 0001 применена при старте. `alembic check`: `No new upgrade operations detected`.
- Полный набор автоматических проверок: **23 passed** на настоящем PostgreSQL, в отдельной базе с автоматически сгенерированным именем. После завершения база удалена.
- В выводе pytest осталось одно предупреждение сторонней библиотеки Starlette об устаревшем псевдониме AnyIO BlockingPortal. Ошибок тестов нет.
- HTTP-сценарий конкурентной покупки: ответы **201 и 409**, один сохранённый заказ, остаток **0**.
- Эмулятор: **4 пользователя × 12 действий**, сводка HTTP-запросов: **51 success, 26 expected_rejection, 0 unexpected_error**, код завершения 0. Получены и покупки, и отмены, и ошибки валидации.
- Все запросы из `queries.sql` выполнены с `ON_ERROR_STOP=1`; проверки согласованности заказов, остатков и статусов не нашли нарушений.
- После `down` и повторного `up` выполнено точное сравнение полных снимков четырёх таблиц, включая цены, ID и время создания/отмены: **снимки совпали**. Сохранены 9 пользователей, 6 товаров, 13 заказов и 13 позиций.
- Команда reset проверена. После reset и повторного seed: **3 пользователя, 5 товаров, 0 заказов, 0 позиций**, остатки **10, 20, 3, 1, 0**.
- С компьютера по HTTP проверены `/health`, `/docs`, `/openapi.json`: везде **200**; HTML Swagger и схема OpenAPI присутствуют. Клики в браузере вручную не проверялись.
- Проверен синтаксис всех 17 Python-файлов.

## Локальные настройки этого компьютера

Стандартные порты 5432 и 8000 заняты другими проектами. В существующем `.env` настроены:

- Swagger: **http://localhost:18080/docs**.
- API health: **http://localhost:18080/health**.
- PostgreSQL для DBeaver: **localhost:15432**, база `playground`, пользователь `playground`, пароль `playground_local`.

При первом запуске стандартный том Docker не смог инициализировать PostgreSQL: диск `/var/lib/docker` в Colima заполнен. Чужие контейнеры, образы, тома и данные не удалялись.

Для проверки создан отдельный каталог `/home/colima/api-db-playground-verification-pgdata` на свободном системном диске виртуальной машины Colima. Он подключён через отдельный именованный том `api-db-playground_verification_data`. Проверка сохранности данных после пересоздания контейнеров выполнена на этом томе, а не на стандартном заполненном Docker-диске.

После проверки этот вариант оставлен работающим для практики. Настройка явно сохранена в `.local/compose.storage.yml`, а `.env` включает её через `COMPOSE_FILE`. Поэтому в текущей папке обычные команды `docker compose up`, `exec`, `down` используют правильное хранилище. После финального сброса полигон содержит только исходные учебные данные; эмулятор завершён.

Не заменяйте существующий `.env` файлом `.env.example`, если хотите сохранить эти локальные настройки. README использует `cp -n`, который не заменяет файл.

## Переносимость

Основной `docker-compose.yml` использует обычный постоянный именованный том PostgreSQL и не зависит от Colima. Локальные `.env` и `.local/` исключены из ZIP-архива, Git и Docker-контекста. В новой папке создайте `.env` из примера и при необходимости выберите свободные порты.

Запуск с основным томом на этом компьютере потребует свободного места на диске Docker. Сам проект и все функциональные проверки успешно выполнены с описанной отдельной настройкой хранилища.


## Дополнение: фронтенд

Фронтенд запущен на http://localhost:18080/. Проверено 26 Python-тестов и 4 JavaScript-теста; все прошли.

Браузерная QA выполнена через Playwright и Google Chrome: 13 проверок прошли на desktop 1440×1000 и mobile 390×844. Browser plugin не был доступен в списке навыков; использован обычный Playwright из временной папки.

Проверены поиск, пустые состояния, создание пользователя и товара, ошибка дублирующегося email, изменение количества и оформление заказа одним кликом, сумма и остатки в БД, просмотр заказа и позиций в PostgreSQL, отмена и повторная отмена, фильтры заказов, три негативных сценария с неизменностью всех четырёх таблиц, JSON журнала, Escape в диалоге, потеря и восстановление сети, мобильные корзина и навигация. Ошибок JavaScript и неожиданных ошибок консоли нет; сообщения о намеренных HTTP 409/422 и отключённой сети ожидаемы.

Ревью по review-agent выявило и позволило исправить потерю клика после редактирования количества, заблокированные кнопки при переходе во время оформления и обработку первоначальной ошибки снимка БД. Исправленный основной сценарий повторно проверен браузером. Дополнительно HTTP-код учебной проверки берётся из ошибки конкретного запроса, а не из общей очереди журнала.

Учебные записи, созданные QA, оставлены в полигоне; существующие данные не сбрасывались.
